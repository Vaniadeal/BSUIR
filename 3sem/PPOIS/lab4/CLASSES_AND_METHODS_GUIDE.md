## Часть 2. Модуль алгоритмов сортировки (`include/sorts/`)

### 1. `SortUtils.hpp` — Утилиты проверки порядка
* **Для чего нужен файл:** Алгоритмам сортировки необходим надежный и универсальный способ узнать, отсортирован ли диапазон данных, без привязки к конкретному контейнеру.

#### Метод `is_sorted_custom(first, last, comp)`
* **Что делает:** Проверяет, упорядочен ли диапазон `[first, last)` по возрастанию (или согласно переданному компаратору `comp`).
* **Сигнатура:**
  ```cpp
  template <typename ForwardIt, typename Compare = std::less<>>
  bool is_sorted_custom(ForwardIt first, ForwardIt last, Compare comp = Compare());
  ```
* **Для чего нужен:**
  * В алгоритме `Bogosort` — это главное условие выхода из цикла случайного перемешивания.
  * В unit-тестах — для проверки корректности результатов сортировок.
  * Принимает любые однонаправленные итераторы (Forward Iterator) и выше (векторы, списки, сырые массивы).

---

### 2. `BogoSort.hpp` — Случайная («обезьянья») сортировка (Вариант 11, Задание 1)
* **Для чего нужен файл:** Реализует первый требуемый вариантом 11 алгоритм сортировки. Служит академическим эталоном недетерминированного алгоритма.

#### Метод `bogo_sort(first, last, comp)`
* **Что делает:** Пока диапазон не упорядочен (проверка через `is_sorted_custom`), случайно переставляет элементы местами с помощью `std::shuffle` и генератора `std::mt19937`.
* **Для чего нужен:** Сортирует последовательность по итераторам произвольного доступа. Применяется на небольших коллекциях ($N \le 6$) в демонстрационных целях и для стресс-тестирования.

#### Метод `bogo_sort_container(container, comp)`
* **Что делает:** Автоматически извлекает `std::begin(container)` и `std::end(container)` и передаёт их в `bogo_sort`.
* **Для чего нужен:** Избавляет пользователя от необходимости вручную вызывать `.begin()` и `.end()`, позволяя писать лаконичный код: `bogo_sort_container(myVector)`.

---

### 3. `InPlaceMergeSort.hpp` — Сортировка слиянием на месте (Вариант 11, Задание 1)
* **Для чего нужен файл:** Реализует второй требуемый вариант алгоритма — классическую сортировку слиянием, модифицированную для работы **без выделения вспомогательного динамического массива $O(N)$ памяти**.

#### Метод `in_place_merge_custom(first, middle, last, comp)`
* **Что делает:** Сливает два соседних уже отсортированных подмассива `[first, middle)` и `[middle, last)` прямо в исходной памяти. Сравнивает элементы слева и справа; если элемент справа меньше, он перемещается на текущую позицию слева, а промежуточные элементы сдвигаются вправо на один шаг.
* **Для чего нужен:** Это фундаментальное ядро алгоритма In-place merge sort. Позволяет объединить результаты рекурсивных сортировок с расходом дополнительной памяти строго $O(1)$.

#### Метод `in_place_merge_sort(first, last, comp)`
* **Что делает:** Рекурсивно делит диапазон пополам по индексу `count / 2`, вызывает саму себя для левой и правой половин, а затем вызывает `in_place_merge_custom`.
* **Для чего нужен:** Обеспечивает устойчивую сортировку больших массивов произвольных объектов в условиях жестких ограничений по оперативной памяти (например, в embedded-системах, где нельзя выделять дублирующий буфер).

#### Метод `in_place_merge_sort_container(container, comp)`
* **Что делает:** Обёртка для сортировки всего контейнера целиком без явного указания итераторов.
* **Для чего нужен:** Удобный интерфейс верхнего уровня для прикладного кода (`in_place_merge_sort_container(students)`).

## Часть 3. Пользовательский класс данных (`Student.hpp`, `Student.cpp`)

* **Для чего нужен класс:** По требованию чеклиста курсa обобщённые алгоритмы и контейнеры должны быть протестированы не только на примитивных типах (`int`), но и на сложном пользовательском типе данных с разделением на `.hpp` и `.cpp`.

### Поля класса `Student`:
* `int id_`: уникальный номер зачётной книжки / студенческого билета. **Для чего нужно:** служит уникальным естественным ключом для идентификации и сравнения студентов по умолчанию.
* `std::string name_`: фамилия и имя студента. **Для чего нужно:** хранит текстовые атрибуты студента для вывода в консоль.
* `double gpa_`: средний балл (Grade Point Average). **Для чего нужно:** используется для демонстрации сортировки с пользовательским компаратором (например, сортировка по успеваемости).

### Методы класса `Student`:
* `Student()`:
  * **Что делает:** Зануляет поля (`id = 0`, `name = ""`, `gpa = 0.0`).
  * **Для чего нужен:** Требуется для поддержки контейнеров по умолчанию (DefaultConstructible).
* `Student(int id, std::string name, double gpa)`:
  * **Что делает:** Инициализирует все поля, используя эффективный перенос строки `std::move(name)`.
  * **Для чего нужен:** Создание полноценных объектов студентов в коде и тестах.
* `int getId() const`, `const std::string& getName() const`, `double getGpa() const`:
  * **Что делают:** Константные геттеры к приватным полям.
  * **Для чего нужны:** Предоставляют безопасный доступ к данным студента для вывода на экран или формирования пользовательских компараторов (инкапсуляция).
* `bool operator<(const Student& other) const`:
  * **Что делает:** Сравнивает текущего студента с другим по `id_ < other.id_`.
  * **Для чего нужен:** Задаёт строгий слабый порядок по умолчанию. Именно благодаря этому оператору `in_place_merge_sort_container(students)` работает «из коробки» без явной передачи лямбда-функции.
* `bool operator==(const Student& other) const` и `bool operator!=(const Student& other) const`:
  * **Что делают:** Проверяют полное совпадение или несовпадение всех полей двух объектов.
  * **Для чего нужны:** Необходимы для юнит-тестов (проверка совпадения ожидаемого и фактического студента) и для поиска студента в контейнере.

## Часть 4. Структура данных графа по Н. Вирту (`include/graph/`)

В книге «Алгоритмы и структуры данных» Никлаус Вирт предложил представление графа, при котором список вершин и списки инцидентных рёбер представляют собой взаимосвязанные динамические структуры на указателях.

```text
  [VertexNode A] <====== nextVertex ======> [VertexNode B]
        ||                                        ||
    firstEdge                                 firstEdge
        ||                                        ||
        \/                                        \/
  [EdgeNode -> B] <==== nextEdge ====> ...   [EdgeNode -> A]
```

### 1. `EdgeNode.hpp` — Узел ребра графа
* **Для чего нужна структура:** Представляет направленную связь от текущей вершины к смежной вершине.
* **Поля:**
  * `VertexNode<T>* target`: прямой указатель на узел целевой вершины. **Для чего нужно:** позволяет за $O(1)$ перейти к данным смежной вершины без повторного поиска по графу.
  * `EdgeNode<T>* nextEdge`: указатель на следующее ребро в списке инцидентности. **Для чего нужно:** организует односвязный/двусвязный обход всех соседей вершины.
  * `EdgeNode<T>* prevEdge`: указатель на предыдущее ребро. **Для чего нужно:** позволяет удалять ребро из середины списка за $O(1)$ без прохода от начала списка.
* **Конструктор `EdgeNode(VertexNode<T>* targetVertex)`:**
  * **Что делает:** Связывает узел ребра с целевой вершиной, обнуляя указатели соседей.
  * **Для чего нужен:** Используется графом при вызове `add_edge`.

---

### 2. `VertexNode.hpp` — Узел вершины графа
* **Для чего нужна структура:** Хранит данные самой вершины и возглавляет список её связей.
* **Поля:**
  * `T value`: полезная нагрузка (число, строка, объект `Student`). **Для чего нужно:** хранит пользовательские данные.
  * `EdgeNode<T>* firstEdge`: указатель на голову двусвязного списка инцидентных рёбер. **Для чего нужно:** точка входа для обхода всех соседей данной вершины.
  * `VertexNode<T>* nextVertex`: указатель на следующую вершину в общем списке графа. **Для чего нужно:** организация глобального списка вершин графа.
  * `VertexNode<T>* prevVertex`: указатель на предыдущую вершину. **Для чего нужно:** организация двусвязного списка для поддержки двунаправленных итераторов (`--it`) и удаления вершины за $O(1)$.
* **Конструкторы `VertexNode(const T&)` и `VertexNode(T&&)`:**
  * **Что делают:** Инициализируют значение вершины (копированием или перемещением).
  * **Для чего нужны:** Используются графом при вызове `add_vertex`.

## Часть 5. Семейство итераторов графа (`include/graph/iterators/`)

Все итераторы полностью совместимы со стандартными алгоритмами C++ (`<algorithm>`), предоставляя стандартные typedef'ы: `iterator_category`, `value_type`, `difference_type`, `pointer`, `reference`.

### 1. `VertexIterator.hpp` — Итераторы вершин (`VertexIterator` и `ConstVertexIterator`)
* **Категория:** `std::bidirectional_iterator_tag` (Двунаправленный итератор).
* **Для чего нужны:** Обеспечивают стандартный обход всех вершин графа от `begin()` до `end()`, а также в обратную сторону (`rbegin()` $\to$ `rend()`).
* **Методы:**
  * `operator*()`: возвращает ссылку `T&` на значение текущей вершины. **Для чего нужен:** чтение и изменение значения вершины (`*it = 50`).
  * `operator->()`: возвращает указатель `T*` на значение вершины. **Для чего нужен:** прямой вызов методов объекта в вершине (`it->getName()`).
  * `operator++()` / `operator++(int)`: перемещает итератор на `nextVertex`. **Для чего нужен:** шаг вперед в циклах `for (auto v : graph)`.
  * `operator--()` / `operator--(int)`: перемещает итератор на `prevVertex` (или на `tail_`, если были в `end()`). **Для чего нужен:** шаг назад, реверсивный обход.
  * `operator==()`, `operator!=()`: сравнение двух итераторов. **Для чего нужен:** условие остановки цикла (`it != graph.end()`).

---

### 2. `EdgeIterator.hpp` — Итератор уникальных рёбер графа
* **Категория:** `std::bidirectional_iterator_tag`.
* **Для чего нужен:** В неориентированном графе ребро между $U$ и $V$ физически хранится в двух списках: у $U$ есть дуга в $V$, а у $V$ — дуга в $U$. `EdgeIterator` решает критически важную задачу — **гарантирует, что при обходе `edge_begin()` $\to$ `edge_end()` каждое ребро вернется ровно один раз** (возвращает пару, только когда $U \le V$).
* **Методы:**
  * `operator*()`: возвращает пару `std::pair<T, T>(u, v)`. **Для чего нужен:** получение концов текущего ненаправленного ребра.
  * `operator++()`: находит следующее каноническое уникальное ребро в графе. **Для чего нужен:** последовательный перебор всех рёбер.
  * `operator--()`: находит предыдущее каноническое ребро. **Для чего нужен:** обратный обход рёбер графа.

---

### 3. `AdjacentVertexIterator.hpp` — Двунаправленный итератор смежных вершин
* **Категория:** `std::bidirectional_iterator_tag`.
* **Для чего нужен:** Обход всех соседей конкретной вершины (например, всех городов, соединённых дорогами с Минском).
* **Методы:**
  * `operator*()`, `operator->()`: дают доступ к значению соседней вершины (`edge_->target->value`).
  * `operator++()`, `operator--()`: перемещаются вперед и назад по списку инцидентности данной вершины.

---

### 4. `ForwardAdjacentVertexIterator.hpp` — Однонаправленный итератор (СПЕЦИФИКА ВАРИАНТА 11)
* **Категория:** **`std::forward_iterator_tag`** (**Однонаправленный итератор**).
* **Для чего нужен:** **Прямое индивидуальное требование Варианта 11**:
  > *«предусмотреть итератор для обхода смежных с ней вершин (forward)»*.
  Намеренно не содержит операторов декремента (`--`), обеспечивая строго однонаправленный проход по смежным вершинам с минимальными накладными расходами.
* **Методы:**
  * `operator*()`: возвращает ссылку на смежную вершину.
  * `operator->()`: доступ к полям смежной вершины через стрелочку.
  * `operator++()` / `operator++(int)`: перемещение только вперед к следующему соседу (`edge_ = edge_->nextEdge`).
  * `operator==()`, `operator!=()`: проверка достижения конца списка смежности.

---

### 5. `IncidentEdgeIterator.hpp` — Итератор инцидентных рёбер
* **Категория:** `std::bidirectional_iterator_tag`.
* **Для чего нужен:** Возвращает не просто соседние вершины, а сами пары рёбер `(u, neighbor)`, выходящие из заданной вершины `u`.
* **Методы:**
  * `operator*()`: возвращает `std::pair<T, T>(u, neighbor)`. **Для чего нужен:** отображение всех связей выбранного узла.
  * `operator++()`, `operator--()`: обход инцидентных рёбер в прямом и обратном направлениях.

---

## Часть 6. Основной контейнер `Graph<T>` (`Graph.hpp`)

Универсальный класс контейнера неориентированного взвешенного/невзвешенного графа на динамической структуре Вирта.

### 1. Управление ресурсами и памятью (Rule of 5)
* `Graph()`:
  * **Что делает:** Создаёт пустой граф.
  * **Для чего нужен:** Инициализация пустого контейнера до добавления элементов.
* `Graph(std::initializer_list<T> init)`:
  * **Что делает:** Принимает список элементов в фигурных скобках: `Graph<int> g = {1, 2, 3}`.
  * **Для чего нужен:** Удобное и наглядное создание тестовых графов в коде.
* `Graph(const Graph& other)`:
  * **Что делает:** Конструктор глубокого копирования (Deep Copy). Создаёт точные независимые копии всех узлов и рёбер.
  * **Для чего нужен:** Предотвращает появление повисших указателей и двойного освобождения памяти при передаче графа по значению.
* `Graph(Graph&& other) noexcept`:
  * **Что делает:** Перемещающий конструктор. За $O(1)$ забирает указатели `head_`, `tail_` и счетчики у временного графа.
  * **Для чего нужен:** Максимальная производительность при возврате графа из функций (Move Semantics).
* `Graph& operator=(const Graph& other)`:
  * **Что делает:** Оператор присваивания глубоким копированием с защитой от самоприсваивания.
  * **Для чего нужен:** Корректное присваивание одного существующего графа другому (`g1 = g2`).
* `Graph& operator=(Graph&& other) noexcept`:
  * **Что делает:** Перемещающее присваивание с предварительным освобождением старой памяти.
  * **Для чего нужен:** Эффективное перемещение (`g1 = std::move(g2)`).
* `~Graph()`:
  * **Что делает:** Деструктор. Вызывает метод `clear()`, гарантируя отсутствие утечек памяти (проверено Valgrind / AddressSanitizer).

---

### 2. Модификаторы графа
* `void clear() noexcept`:
  * **Что делает:** Построчно удаляет все рёбра всех вершин, а затем все вершины, обнуляя счетчики.
  * **Для чего нужен:** Полный сброс графа в исходное пустое состояние.
* `bool add_vertex(const T& val)` / `bool add_vertex(T&& val)`:
  * **Что делает:** Создаёт новую вершину и добавляет её в хвост двусвязного списка вершин. Если вершина с таким значением уже есть, добавление отменяется и возвращается `false`.
  * **Для чего нужен:** Наполнение графа вершинами.
* `bool add_edge(const T& u, const T& v)`:
  * **Что делает:** Добавляет неориентированное ребро между $U$ и $V$. Добавляет `EdgeNode` в список рёбер $U$ и парный `EdgeNode` в список рёбер $V$.
  * **Для чего нужен:** Создание связей между узлами. Бросает исключение при попытке создать петлю ($U = V$) или при отсутствии вершин.
* `bool remove_edge(const T& u, const T& v)`:
  * **Что делает:** Находит и удаляет встречные узлы рёбер из списков смежности обеих вершин.
  * **Для чего нужен:** Разрыв связи между двумя узлами без удаления самих узлов.
* `bool remove_vertex(const T& val)`:
  * **Что делает:** Удаляет вершину, все её инцидентные рёбра, а также удаляет ссылки на неё из всех смежных с ней вершин.
  * **Для чего нужен:** Корректное удаление узла с сохранением целостности графа.
* `iterator erase(const iterator& pos)`:
  * **Что делает:** Удаляет вершину, на которую указывает итератор `pos`, и возвращает итератор на следующую вершину.
  * **Для чего нужен:** Удаление элементов графа в стиле STL прямо во время итерирования.
* `edge_iterator erase(const edge_iterator& pos)`:
  * **Что делает:** Удаляет ребро по итератору ребер и возвращает итератор на следующее ребро.
  * **Для чего нужен:** Удаление связей во время обхода рёбер.
* `void swap(Graph& other) noexcept`:
  * **Что делает:** За $O(1)$ меняет указатели двух графов местами.
  * **Для чего нужен:** Быстрый обмен без копирования данных.

### 3. Информационные методы и метрики
* `bool empty() const`:
  * **Что делает:** Проверяет, пуст ли граф (`vertexCount_ == 0`).
  * **Для чего нужен:** Базовые проверки перед началом алгоритмов.
* `size_type vertex_count() const` и `size_type edge_count() const`:
  * **Что делают:** Возвращают количество вершин $|V|$ и уникальных рёбер $|E|$.
  * **Для чего нужны:** Анализ размеров графа.
* `bool has_vertex(const T& val) const`:
  * **Что делает:** Ищет узел вершины со значением `val`.
  * **Для чего нужен:** Проверка существования вершины перед добавлением связей.
* `bool has_edge(const T& u, const T& v) const`:
  * **Что делает:** Проверяет, существует ли ребро между $U$ и $V$.
  * **Для чего нужен:** Проверка связности конкретной пары узлов.
* `size_type degree(const T& val) const`:
  * **Что делает:** Считает длину списка инцидентности вершины.
  * **Для чего нужен:** Вычисление степени вершины (количества дорог/связей у узла).
* `size_type edge_degree(const T& u, const T& v) const`:
  * **Что делает:** Вычисляет степень ребра по классической формуле: $\deg(u) + \deg(v) - 2$.
  * **Для чего нужен:** **Требование варианта графа**: определение количества смежных рёбер (рёбер, имеющих с данным ребром хотя бы одну общую вершину).

---

### 4. Фабричные методы итераторов
* `begin()`, `end()`, `cbegin()`, `cend()` — получение итераторов по вершинам.
* `rbegin()`, `rend()`, `crbegin()`, `crend()` — получение обратных итераторов по вершинам.
* `edge_begin()`, `edge_end()` — получение итераторов по всем уникальным рёбрам графа.
* `adjacent_vertex_begin(u)`, `adjacent_vertex_end(u)` — двунаправленный обход соседей вершины `u`.
* `forward_adjacent_begin(u)`, `forward_adjacent_end(u)` — **однонаправленный обход соседей по Варианту 11**.
* `incident_edge_begin(u)`, `incident_edge_end(u)` — обход пар рёбер, выходящих из `u`.

---

### 5. Операторы сравнения и потоковый вывод
* `operator==`, `operator!=`:
  * **Что делают:** Проверяют два графа на структурную эквивалентность (совпадение всех вершин и рёбер).
  * **Для чего нужны:** Сравнение графов в unit-тестах и бизнес-логике.
* `operator<`, `operator>`, `operator<=`, `operator>=`:
  * **Что делают:** Лексикографическое сравнение графов (по числу вершин, рёбер и значениям).
  * **Для чего нужны:** Позволяют хранить сами графы в качестве ключей в `std::map` или элементами в `std::set`.
* `friend std::ostream& operator<<(std::ostream& os, const Graph<T>& g)`:
  * **Что делает:** Форматирует граф в поток вывода: печатает число вершин, число рёбер, список вершин и список рёбер.
  * **Для чего нужен:** Наглядная печать графа в консоль. По требованию преподавателя список элементов печатается через **стандартный алгоритм `std::for_each`**.
